# Remaining Files and Setup Checklist

## What to add beyond the current folder tree

The supplied tree is a useful directory plan, but it is not yet a
runnable Next.js application. This checklist identifies the key files
and configuration you still need.

## 2. Next.js application files

Add or ensure: - `src/app/layout.tsx` --- root HTML/body layout and
providers. - `src/app/globals.css` --- global styles and Tailwind
directives/imports. - `src/app/page.tsx` --- landing page or redirect. -
`src/app/not-found.tsx` --- not-found page. - `src/app/error.tsx` ---
route error boundary if needed. - `src/app/loading.tsx` --- optional
global loading UI.

The route-group folders should contain `page.tsx` files for actual
pages. A directory alone does not create a visible page.

├── plans/

│   └── [id]/route.ts
├── invoices/
│   ├── route.ts
│   └── [id]/route.ts
├── payments/
│   ├── route.ts
│   └── [id]/route.ts
├── discounts/

Only add methods/endpoints that the application actually needs. For
Auth.js, follow the route path and handler setup for the Auth.js version
selected by the team; do not create an empty `[...nextauth]` route
without configuring the provider and handlers.

## 5. Environment variables

Create `.env.example` with placeholders only. For example:

``` dotenv
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DATABASE"
AUTH_SECRET="replace-with-a-long-random-secret"
APP_URL="http://localhost:3000"

# Add only if the feature is implemented:
RESEND_API_KEY=""
PAYMENT_PROVIDER_SECRET=""
PAYMENT_WEBHOOK_SECRET=""
CRON_SECRET=""
```

Use the variable names required by the exact authentication and database
libraries selected. Keep real values in `.env.local` or the deployment
environment. Never commit those files.

## 6. Prisma files

-   `prisma/schema.prisma`: models, enums, relations and indexes.
-   `prisma/migrations/`: generated by Prisma migration commands; do not
    manually invent migration history.
-   `prisma/seed.ts`: demo users, products, plans and sample data.

Coordinate the schema with Member 3 before the first migration. Invoice
lines should preserve the price and tax values used at invoice time.

## 7. Tests

Add tests as features are implemented:

-   Unit: price calculations, discount eligibility, tax calculations,
    subscription state transitions.
-   Integration: API + database operations, invoice creation, payment
    recording.
-   End-to-end: register/login, create product/plan, create
    subscription, generate invoice, record payment.

## 8. Important note about the current tree

The tree is a planned architecture, not a requirement to create every
file immediately. Avoid committing dozens of empty files. Create
runnable configuration first, then implement each route/module with
tests. Add `page.tsx` and `route.ts` files only when they contain
working behavior or a deliberate placeholder page.

## 9. Minimum files to make the project runnable

Before feature development, ensure at least: - `package.json` -
`next.config.ts` - `tsconfig.json` - `eslint.config.mjs` -
`src/app/layout.tsx` - `src/app/globals.css` - `src/app/page.tsx` -
`.gitignore` - `.env.example` - `prisma/schema.prisma` (once Prisma is
installed/configured) - `README.md`

Check compatibility between the Next.js, Tailwind CSS, Prisma and
Auth.js versions chosen by the team before copying configuration
examples.
